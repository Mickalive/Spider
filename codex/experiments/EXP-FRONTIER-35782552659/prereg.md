## 2. State, action, target, unit of analysis

**State representation (raw -> derived, no BrowserGym required):**

Losses disclosed: visual layout pixels, timing, auth token values beyond key presence, AX tree — bounded to tested header/body/auth aliasing + mixed.
- Hierarchical component representation: For each mechanism episode, parse `action_template` string to extract semantic components: `url_segments` (non-slot path tokens), `query_keys` (keys before `=` or `${slot}`), `header_keys` (e.g., `ApiKey`, `X-Reset-Token`), `body_fields` (JSON keys), `auth_scopes` (permission values). Extract via regex `\$\{[^}]+\}` for slots and string splitting, no hidden_expected access. Components are sets; themes are clusters of episodes by Jaccard(component_set_i, component_set_j) >=0.6. AX fields None for synthetic; no 1280x720 viewport needed per Director rationale.
- Forbidden: `alias_family`, `query_key`, `target_prefix`, `routing_prefix`, `target_style`, `path_style`, `header_key`, `body_field`, `auth_scope`, `expected_template`, `resource` answer labels are NOT in derived_context nor in component extraction; stored only as hidden `expected` metadata for scoring. Audit verifies no forbidden reads via harness `hierarchical_retrieve`/`flat_retrieve`/`reconstruct_resolve` signatures and index manifest audit.

**Action representation:**
- Mechanism `action_template` is URL/header/body/auth template strings with `${slot}` (e.g., `/users/${id}`, `ApiKey: ${token}` vs `X-Reset-Token: ${token}`, `{"apiKey":"${token}"}` vs `{"key":"${token}"}`, `scope:${perm}`) and for mixed tasks simultaneously header+body+query slots. Reconstruction after retrieval may score each candidate template's structural match to derived state and rewrite via `adopt-any-observed-key-not-in-registry + rewrite_template_multi` (alphabetically-sorted multi-adoption) before `_bind`, conditioned only on `(intent, derived_state, retrieved_candidates)`. No hidden_expected access.

**Target (primary measurand):**
- Per-task outcome in `{correct_resolution, false_accept, UNKNOWN}` (mutually exclusive, sum to 1 per stratum).
  - `correct_resolution` = retrieval set contains rewritable candidate and reconstruction selects/rewrites to alias-correct template with `bound_action` (url+header+body jointly for mixed) equals `expected_bound` (hidden_expected_template bound with params).
  - `false_accept` = retrieved+reconstructed to wrong template or bound incorrectly or should have abstained.
  - `UNKNOWN` = correctly abstains when no applicable mechanism or gated confidence<0.80.
- Retrieval measurands per task:
  - `recall@k` = 1 if retrieved candidates contain at least one mechanism whose template after genuine reconstruction yields correct bound (component-recall), else 0. Coverage = mean recall@k over pooled.
  - `distinct_components` = number of distinct semantic component types (header vs body vs auth) represented in retrieved set; density = distinct_components / k.
  - Coverage gain = hierarchical coverage - best flat coverage (max of TFIDF-K5 and EMBED-K5). Density gain = hierarchical density - best flat density.
- Secondary: calibration — `ECE` over 5 confidence bins (reconstruction-derived confidence), abstention precision/recall; per-family (header/body/auth) and held-out-9 and mixed-10 breakdowns; adaptive k distribution for hierarchical.
- Mixed multi-channel target: correct only if ALL channels (header + body + query) jointly correctly rewritten and bound; partial counts as false_accept.

**Unit of analysis:** Single `retrieve(k) + reconstruct_resolve + bind` call per task. Paired design: each task evaluated under each pipeline (within-task). Resampling unit is task family (block bootstrap over tasks grouped by family header/body/auth/mixed to respect trajectory-grouped structure per Director question).
