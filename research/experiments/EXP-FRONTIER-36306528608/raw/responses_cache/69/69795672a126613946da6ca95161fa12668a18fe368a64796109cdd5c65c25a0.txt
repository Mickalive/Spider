            <p>You know the drill. Twenty students, one shared sandbox, and someone runs a DELETE that takes out everyone&#39;s data five minutes into class. Half the room is debugging someone else&#39;s mess. The other half hasn&#39;t started because they&#39;re still installing dependencies.</p>
<p>ReqRes Classrooms put an end to that. Every student gets their own API key, their own isolated data, and you get a live dashboard that shows exactly who&#39;s making progress and who needs a nudge.</p>
<h2>Set up in minutes, not hours</h2>
<p>A classroom wraps a ReqRes project with student-level isolation. Create one, pick a template, generate API keys - and your students are ready to go.</p>
<h3>Pick a template (or start blank)</h3>
<p>Templates pre-load your classroom with collections, schemas, and seed data so nobody&#39;s staring at an empty screen. Three are built in today:</p>
<p><strong>Todo App</strong> - A <code>Todos</code> collection with 10 records. Fields include <code>title</code>, <code>completed</code>, and <code>priority</code> (low/medium/high). Seven guided exercises walk students from their first GET to filtering and pagination.</p>
<p><strong>User Directory</strong> - A <code>Users</code> collection with 20 realistic records. Fields like <code>name</code>, <code>email</code>, <code>role</code> (admin/editor/viewer), <code>avatar</code>, and <code>active</code>. Seven exercises covering everything from basic CRUD to role-based filtering.</p>
<p><strong>QA Test Target</strong> - Two collections (<code>Users</code> + <code>Products</code>, 30 records) built for QA-focused courses. Nine exercises including validation testing (expect a 400!), response time assertions, and concurrent request tests.</p>
<p>Or start blank and build your own.</p>
<h3>Add students in bulk</h3>
<p>Type student names (one per line) and the system generates a unique API key for each. Copy them all at once - tab-separated for pasting into a spreadsheet - or download a CSV.</p>
<p>Students don&#39;t need a ReqRes account. They just need their key.</p>
<h3>Students start making real requests</h3>
<p>From curl, Postman, the browser console, or their own code - students hit real endpoints, authenticated with their own key:</p>
<pre><code class="language-bash">curl https://reqres.in/api/collections/todos/records \
  -H &quot;x-api-key: stu_abc123...&quot;
</code></pre>
<pre><code class="language-bash">curl -X POST https://reqres.in/api/collections/todos/records \
  -H &quot;x-api-key: stu_abc123...&quot; \
  -H &quot;Content-Type: application/json&quot; \
  -d &#39;{&quot;data&quot;: {&quot;title&quot;: &quot;Finish homework&quot;, &quot;completed&quot;: false, &quot;priority&quot;: &quot;high&quot;}}&#39;
</code></pre>
<p>Each student sees only their own records. One student&#39;s POST never shows up in another student&#39;s GET.</p>
<h2>See who&#39;s stuck before they raise their hand</h2>
<p>The classroom dashboard gives you two views: <strong>Students</strong> and <strong>Activity</strong>.</p>
<h3>Students</h3>
<p>A roster of everyone in your classroom - their status, lifetime request count, and last active timestamp. From here you can reveal masked API keys, add or remove students, view collection schemas, apply templates, or reset all data between cohorts (student keys stay intact).</p>
<h3>Activity</h3>
<p>A live view (auto-refreshes every 30 seconds) that surfaces per-student metrics over the last 7 days: total requests, error rate, distinct endpoints hit, and last active time.</p>

<h3>Drill into any student&#39;s requests</h3>
<p>Click a student row to see their last 25 API requests - method, path, status code, latency, and timestamp. Click a request to expand it further and see the full headers, request body, and response body.</p>
<p>This is where you spot the actual mistake. A malformed JSON body, a wrong endpoint, a missing header - it&#39;s all there.</p>
<h3>Export everything</h3>
<p>One click to download a CSV of your entire classroom&#39;s activity: student name, request counts by method, error count, and last active time.</p>
<h2>Templates that teach, not just demonstrate</h2>
<p>When you apply a template, the Getting Started section shows numbered exercises you can share with your class. They&#39;re suggestions, not enforced rules - use them as-is or adapt them to your curriculum.</p>
<p>Templates also pre-configure schema validation. The Todo App template, for example, requires a <code>title</code> field and restricts <code>priority</code> to <code>low</code>, <code>medium</code>, or <code>high</code>. Students who POST invalid data get a real 400 error with a clear message. That&#39;s not a bug - that&#39;s the lesson.</p>
<h2>What students see (and don&#39;t)</h2>
<p>Students don&#39;t get a dashboard. They get an API key and whatever instructions you give them.</p>
<p>This is by design. The whole point is learning how APIs actually work - sending HTTP requests, reading status codes, interpreting response bodies. They use curl, Postman, Insomnia, or their own code. They authenticate with <code>x-api-key</code>. They work against a real API that behaves like a real API.</p>
<p>Their data is isolated. Their requests are logged (for you, not them). They can&#39;t see or touch anyone else&#39;s records.</p>
