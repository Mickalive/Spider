        >
            <p>Adding API tests to CI shouldn&#39;t mean maintaining mock servers, Docker containers, or fragile test fixtures. ReqRes is a <a href="/blog/free-api-for-testing">free hosted API</a> that&#39;s always available, returns stable payloads, and supports auth - so your CI tests run reliably without infrastructure overhead. Here&#39;s how to wire it up.</p>
<h2>Why do CI API tests need a stable external API?</h2>
<p>Common approaches create friction:</p>
<ul>
<li><strong>Local mock servers</strong> add Docker/startup complexity, slow down pipelines, and diverge from real API behaviour</li>
<li><strong>Shared staging environments</strong> are flaky, slow, and block other teams</li>
<li><strong>Inline mocking</strong> (Jest mocks, <code>page.route</code>) only tests your mocks, not your actual integration</li>
</ul>
<p>What you want: an API that&#39;s always up, returns predictable data, supports auth, and doesn&#39;t require any setup in CI.</p>
<p>ReqRes gives you exactly that - a real REST API you can hit from any CI runner without provisioning anything.</p>
<h2>How do I test APIs in GitHub Actions?</h2>

<h3>With cURL (simplest)</h3>

<h2>What makes a good CI API test suite?</h2>
<p>Keep it practical:</p>
<p><strong>Test the happy path first:</strong></p>
<ul>
<li>GET returns 200 with expected data shape</li>
<li>POST returns 201 with an ID</li>
<li>Auth endpoints return tokens</li>
</ul>
<p><strong>Test auth failures:</strong></p>
<ul>
<li>Missing <code>x-api-key</code> returns 401</li>
<li>Invalid key returns 403</li>
</ul>
<p><strong>Test edge cases:</strong></p>
<ul>
<li>Invalid payloads return 400</li>
<li>Missing resources return 404</li>
</ul>
<p><strong>Keep tests fast:</strong></p>
<ul>
<li>10-20 targeted assertions beat 200 slow integration tests</li>
<li>Focus on critical paths, not exhaustive coverage</li>
</ul>
<p><strong>Debug with logs:</strong></p>
<ul>
<li>ReqRes logs every request with headers and response times</li>
<li>When tests fail, check logs to see exactly what was received</li>
</ul>
<p>For detailed endpoint information, see the <a href="/docs">API documentation</a>.</p>
<h2>What about rate limits in CI?</h2>
<p>Practical guidance:</p>
<ul>
<li><strong>ReqRes free tier</strong> handles CI test suites comfortably for most teams</li>
<li><strong>Parallel pipelines</strong> across many repos may need higher limits - consider upgrading</li>
<li><strong>Add retry logic</strong> with exponential backoff (3 retries, starting at 1 second)</li>
<li><strong>Don&#39;t over-test</strong> - run smoke tests on push, full suite on PR/merge</li>
</ul>
<p>Example retry wrapper for cURL:</p>
<pre><code class="language-bash">retry_curl() {
  local max_attempts=3
  local delay=1
  local attempt=1

  while [ $attempt -le $max_attempts ]; do
    if curl &quot;$@&quot;; then
      return 0
    fi
    echo &quot;Attempt $attempt failed. Retrying in ${delay}s...&quot;
    sleep $delay
    delay=$((delay * 2))
    attempt=$((attempt + 1))
  done
  return 1
}
</code></pre>
