            <p>Postman is the most popular tool for testing APIs, but you still need an API to test against. ReqRes gives you a free, hosted REST API with real endpoints, authentication, and persistent data - no backend setup required. This guide walks you through a complete Postman workflow from first request to CI automation.</p>
<h2>What you&#39;ll need</h2>
<ul>
<li>Postman (free desktop app or web version)</li>
<li>A free ReqRes API key (takes 10 seconds at reqres.in)</li>
<li>That&#39;s it. No servers, no databases, no Docker.</li>
</ul>
<h2>How do I set up Postman with a test API?</h2>
<p>Setting up Postman with ReqRes takes under two minutes.</p>
<h3>1. Get your API key</h3>
<p>Create a free ReqRes account and grab your API key from the dashboard:</p>
<p><a href="https://app.reqres.in/?next=/api-keys">https://app.reqres.in/?next=/api-keys</a></p>
<h3>2. Create a Postman environment</h3>
<p>In Postman, click <strong>Environments</strong> in the sidebar and create a new environment called &quot;ReqRes&quot;.</p>
<p>Add these variables:</p>
<table>
<thead>
<tr>
<th>Variable</th>
<th>Initial Value</th>
</tr>
</thead>
<tbody><tr>
<td>base_url</td>
<td><a href="https://reqres.in">https://reqres.in</a></td>
</tr>
<tr>
<td>api_key</td>
<td>your-api-key-here</td>
</tr>
</tbody></table>
<h3>3. Use the environment in requests</h3>
<p>In your request headers, add:</p>
<pre><code class="language-http">x-api-key: {{api_key}}
</code></pre>
<p>Your request URL becomes:</p>
<pre><code class="language-text">{{base_url}}/api/users
</code></pre>
<h3>cURL equivalent</h3>
<p>For terminal users, every request in this guide works with curl:</p>
<pre><code class="language-bash">curl &quot;https://reqres.in/api/users?page=2&quot; \
  -H &quot;Content-Type: application/json&quot; \
  -H &quot;x-api-key: YOUR_API_KEY&quot;
</code></pre>

<h2>How do I test authentication flows?</h2>
<p>ReqRes supports two authentication modes. This is what sets it apart from JSONPlaceholder and other fake APIs.</p>
<h3>API key authentication (for <code>/api/*</code> endpoints)</h3>
<p>Use the <code>x-api-key</code> header for admin and API-level operations:</p>
<pre><code class="language-bash">curl &quot;https://reqres.in/api/users&quot; \
  -H &quot;x-api-key: YOUR_API_KEY&quot;
</code></pre>
<p>This works for all <code>/api/*</code> endpoints including collections, users, and management operations.</p>
<h3>App user authentication (for <code>/app/*</code> endpoints)</h3>
<p>For user-scoped endpoints, you need a session token. Here&#39;s the flow:</p>
<p><strong>Step 1: Create a magic link request</strong></p>
<pre><code class="language-bash">curl -X POST &quot;https://reqres.in/api/auth/magic-link&quot; \
  -H &quot;Content-Type: application/json&quot; \
  -H &quot;x-api-key: YOUR_API_KEY&quot; \
  -d &#39;{&quot;email&quot;: &quot;test@example.com&quot;}&#39;
</code></pre>
<p><strong>Step 2: Get the session token</strong></p>
<p>In development, the magic link token is returned directly. Use it to get a session:</p>
<pre><code class="language-bash">curl -X POST &quot;https://reqres.in/api/auth/verify&quot; \
  -H &quot;Content-Type: application/json&quot; \
  -H &quot;x-api-key: YOUR_API_KEY&quot; \
  -d &#39;{&quot;token&quot;: &quot;MAGIC_LINK_TOKEN&quot;}&#39;
</code></pre>
<p><strong>Step 3: Use the session token</strong></p>
<pre><code class="language-bash">curl &quot;https://reqres.in/app/collections/todos/records&quot; \
  -H &quot;Authorization: Bearer YOUR_SESSION_TOKEN&quot;
</code></pre>
<h3>Common mistake</h3>
<p>Using <code>x-api-key</code> on <code>/app/*</code> paths returns <code>401 Unauthorized</code>. App paths require a Bearer token from a user session.</p>
<table>
<thead>
<tr>
<th>Path</th>
<th>Header Required</th>
</tr>
</thead>
<tbody><tr>
<td><code>/api/*</code></td>
<td><code>x-api-key: YOUR_API_KEY</code></td>
</tr>
<tr>
<td><code>/app/*</code></td>
<td><code>Authorization: Bearer &lt;token&gt;</code></td>
</tr>
</tbody></table>
<h2>How do I add Postman tests and assertions?</h2>
<p>Postman lets you write JavaScript tests in the <strong>Tests</strong> tab. Here are practical examples.</p>
<h3>Check status code</h3>
<pre><code class="language-javascript">pm.test(&quot;Status code is 200&quot;, () =&gt; {
    pm.response.to.have.status(200);
});
</code></pre>
<h3>Validate response structure</h3>
<pre><code class="language-javascript">pm.test(&quot;Response has user data&quot;, () =&gt; {
    const json = pm.response.json();
    pm.expect(json.data).to.be.an(&quot;array&quot;);
    pm.expect(json.data.length).to.be.greaterThan(0);
});
</code></pre>
<h3>Check required fields</h3>
<pre><code class="language-javascript">pm.test(&quot;User has required fields&quot;, () =&gt; {
    const user = pm.response.json().data[0];
    pm.expect(user).to.have.property(&quot;id&quot;);
    pm.expect(user).to.have.property(&quot;email&quot;);
    pm.expect(user).to.have.property(&quot;first_name&quot;);
});
</code></pre>
<h3>Validate response time</h3>
<pre><code class="language-javascript">pm.test(&quot;Response time is under 500ms&quot;, () =&gt; {
    pm.expect(pm.response.responseTime).to.be.below(500);
});
</code></pre>
<h3>Save values for chaining requests</h3>
<pre><code class="language-javascript">pm.test(&quot;Save user ID for next request&quot;, () =&gt; {
    const json = pm.response.json();
    pm.environment.set(&quot;user_id&quot;, json.data[0].id);
});
</code></pre>
<h2>How do I run Postman collections in CI?</h2>
<p>Running your Postman tests in CI ensures your API integration stays healthy.</p>
<h3>Export your collection</h3>
<ol>
<li>In Postman, right-click your collection</li>
<li>Select <strong>Export</strong></li>
<li>Choose <strong>Collection v2.1</strong></li>
<li>Save as <code>reqres-tests.json</code></li>
</ol>
<p>Export your environment the same way.</p>
<h3>Install Newman</h3>
<p>Newman is Postman&#39;s CLI runner:</p>
<pre><code class="language-bash">npm install -g newman
</code></pre>
<h3>Run locally</h3>
<pre><code class="language-bash">newman run reqres-tests.json -e reqres-environment.json
</code></pre>
<h3>GitHub Actions workflow</h3>
<pre><code class="language-yaml">name: API Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Newman
        run: npm install -g newman

      - name: Run Postman tests
        run: newman run reqres-tests.json -e reqres-environment.json
        env:
          REQRES_API_KEY: ${{ secrets.REQRES_API_KEY }}
</code></pre>
<p>Why this works: ReqRes is always available, returns stable payloads, and requires no mock setup. Your CI tests hit a real API and catch real integration issues.</p>
<p>For avoiding rate limits and handling retries in CI, see our <a href="/blog/qa-automation-with-reqres">QA automation guide</a>.</p>
<h2>Why use a real API instead of mocking everything?</h2>
<p>Mocks give false confidence. Your tests pass, but your integration might not. You&#39;re testing your mock, not your code&#39;s ability to handle real HTTP responses.</p>
<p>Real APIs catch issues mocks miss: network errors, auth failures, payload validation, rate limiting, and response timing. These are the bugs that slip through to production when you only test against hardcoded responses.</p>
<p>ReqRes bridges the gap. It&#39;s as easy to use as a mock - no servers, no database setup, no DevOps. But it returns real HTTP responses with real status codes, headers, and response times.</p>
