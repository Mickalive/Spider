## 2. State, action, target, unit of analysis

**State representation (raw → derived):**
- Raw (live BrowserGym conditional): Playwright at viewport 1280x720, CDP AX tree snapshot, observed `url`, `method` (GET/POST), `headers_observed` (standard headers via CDP/network), `body_observed` (JSON string/body if present via network/DOM), plus `intent` string (goal). Derived: `url_path` (split `/`), `url_query` dict (parse `?k=v`), `url_segments` list, `header_keys_observed` (lowercased keys), `body_json_keys` (parsed JSON keys if applicable), `ax_tree_text_hash` (hash of visible text for verification), truncated AX text 2k tokens for parsing. Losses disclosed: visual layout pixels, timing, auth/session token values beyond key presence — if they matter for broader resolution, effect bounded to tested header/body/auth aliasing + mixed.
- Raw (synthetic orthogonal+mixed): `url` string as observed, `method`, synthetic `headers_observed`/`body_observed` dicts (for mixed, both headers_observed and body_observed and url_query contain aliased keys simultaneously). Derived same fields without AX tree to isolate orthogonal alias mechanism plus mixed credit.
- Forbidden: `alias_family`, `query_key`, `target_prefix`, `routing_prefix`, `target_style`, `path_style`, `header_key`, `body_field`, `auth_scope`, `expected_template`, `resource` answer labels are NOT in derived context; stored only as hidden `expected` metadata for scoring, not passed to methods. Audit verifies no read of forbidden keys and no constant confidence. Mixed stratum forbids hidden mixed_template answer.

**Action representation:**
- Mechanism `action_template` is URL/header/body/auth template strings with `${slot}` (e.g., `/users/${id}`, `ApiKey: ${token}` vs `X-Reset-Token: ${token}`, `{"apiKey":"${token}"}` vs `{"key":"${token}"}`, `scope:${perm}`) and for mixed tasks simultaneously header+body+query slots (e.g., headers `{ApiKey:${token}}` + body `{"apiKey":"${token}"}` + url `?perm=${perm}`). Binding via deterministic `kernel._bind` plus header/body field substitution. Genuine reconstruction may (a) score each candidate template's structural match to derived state (count `${}` slots, match segments, detect query/header/body key presence, AX parsing) and select best, and/or (b) rewrite template structure before `_bind` (path↔query, header rename ApiKey↔X-Reset-Token↔X-Api-Key, body field rename apiKey↔key↔api_token, permission scope mapping, and for mixed jointly rewrite all three channels) conditioned only on `(intent, derived_state, retrieved_template/candidates)`. No hidden_expected access. For mixed, rewriter must compose single-channel rewrites generically, not memorize mixed fixture. Confidence must be derived from normalized structural/model score and gated UNKNOWN at <0.80 for ECE.

**Target (primary measurand, sequenced):**
- Per-task outcome in `{correct_resolution, false_accept, UNKNOWN}` (mutually exclusive, sum to 1 per stratum).
  - `correct_resolution` = adapter selects (or rewrites to) alias-correct template and `bound_action` (url+header+body jointly for mixed) equals `expected_bound` (hidden_expected_template bound with params, including header/body field equality).
  - `false_accept` = selects wrong template or binds incorrectly when should abstain/select correct; includes resolving when should UNKNOWN.
  - `UNKNOWN` = correctly abstains when no applicable mechanism (no-applicable/empty) or calibrated gate `confidence<0.80`.
- G0 gate target: LEARNED vs RULE difference on pooled 40 correct and ECE; mixed-10 joint correctness diagnostic.
- Secondary: calibration — `ECE` over 5 confidence bins (confidence derived from structural/model score), abstention precision/recall; per-family (header/body/auth) and held-out-3 subset plus mixed-10 subset breakdown; live vs synthetic breakdown; training cost/stability (wall-clock, tokens/calls, variance/CV across 3 seeds); verification economics (retrieval+reconstruction+verification steps, cost per task vs RAG/verbatim).
- Mixed multi-channel target: correct only if ALL channels (header + body + query) are jointly correctly rewritten and bound; partial channel correct counts as false_accept.

**Unit of analysis:** Single `resolve+bind(+optional genuine rewrite)` call per task. Paired design: each task evaluated under each method (within-task). Resampling unit is task (block bootstrap over tasks, trajectory-grouped for live BrowserGym if tasks share site/session). Training stability unit is seed.

## 3. Sampling policy and holdout

**Registry construction (frozen, no outcome leakage):**
- Synthetic orthogonal alias-OOD: 30 tasks = 3 families ×10 intents.
  - Families: (a) header-based (`ApiKey: ${token}` vs `X-Reset-Token: ${token}` vs `X-Api-Key: ${token}` vs `Authorization: Bearer ${token}`), (b) body JSON field (`{"apiKey":"${token}"}` vs `{"key":"${token}"}` vs `{"api_key":"${token}"}` vs `{"token":"${token}"}`), (c) auth permission (`scope=read` vs `admin_scope=${perm}` vs `X-Scope: ${perm}`).
  - Per task: registry has 1 training mechanism (one alias form at 0.9), 1 distractor alias form at 0.9, 1 low-confidence distractor at 0.8. Test query uses held-out alias form with same semantic intent string as training (so exact matcher would succeed if it ignored template aliasing). Train template never equals test template.
  - Within each family, 7 tasks standard variations covered by documentation examples, 3 held-out variations (novel header `X-Api-Key`, body field `api_token`, permission `X-Scope`) requiring structural generalization. Report overall 30 plus held-out-9 subset.
- Synthetic mixed multi-channel alias-OOD: 10 tasks where aliasing spans header+body+query within one request (e.g., header `X-Reset-Token: ${token}` + body `{"key":"${token}"}` + query `?permission=${perm}` simultaneously aliased). Registry training mechanisms are single-channel only; test mixed template is novel composition not seen during training nor in any registry entry. Requires joint multi-field rewriting conditioned on derived_context containing all three observed keys. Report mixed-10 subset and pooled alias-OOD 40. Sequencing gate includes this composition — trained only on single-channel, evaluated on mixed for compositional generalization.
- Live BrowserGym alias-OOD (conditional on G0 pass): Attempt 20 WebShop +20 ALFWorld sampled via BrowserGym 0.14.3 at 1280x720 with CDP AX tree. Map to same mechanism abstraction (intent = natural language goal / observation summary, template = action with slots manifested as header/body/URL aliasing in real request). Registry built from training trajectories (distinct intent strings), test tasks are held-out goal variations where alias manifests in observed AX/DOM headers/body/URL. No test live template verbatim in registry. Add 10 live mixed tasks if feasible where real request shows header+body+query co-occurring. If G0 fails, live stage is withheld or reported as exploratory 0 tasks with disclosure to save compute; if offline unavailable or truncation >50%, mark exploratory and bound confirmatory claim to synthetic pooled+mixed only.
- Exact-match: 12 tasks where test `intent` equals registry intent verbatim, same slot names, preconditions match — no aliasing required.
- No-applicable: 12 tasks where test intent OOD with no covering mechanism (correct answer UNKNOWN).
- Empty-registry: 6 tasks with empty registry → UNKNOWN 100%.
- Total synthetic: 70 tasks per method ×7 methods = 490 calls (primary gate). Live adds up to 50×7=350 calls conditional only if G0 passes and BrowserGym healthy.

**Holdout integrity:**
- Alias families and mixed stratum stratified; train/test alias forms and mixed compositions disjoint. No test template verbatim in registry (0/40 synthetic leakage check; same for live if attempted). TF-IDF/embedding fit on train registry strings only.
- Genuine rule set and LEARNED training data derived from training alias documentation only; held-out alias forms and mixed compositions require structural inference.
- Derived context filtered to exclude forbidden keys via harness `derive_state(observed_url, headers_observed, body_observed, ax_tree)` that outputs only allowed fields.
- Seeds deterministic (`np.random.RandomState(42)`, `random.seed(42)`; LEARNED uses 42,43,44 for stability), no unseeded calls. BrowserGym Playwright viewport fixed 1280x720.
- Live tasks split by site (WebShop vs ALFWorld) with no site identity leakage into retriever; retriever fit on train registry only. Sequencing does not leak test signals into LEARNED training (training logs auditable for 0/10 mixed in training data).

**Holdout unit:** Task-level; preprocessing fit on TRAIN only; site/task identity does not leak.
