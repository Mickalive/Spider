## 1. Strategic Context

This experiment is mandated by the Global Research Director (director_mandate.action=CONTINUE, claim_id=C-SEMANTIC-RESOLVE). It addresses the construct-validity defects that caused EXP-GRAPH-36272373909 to be MEASUREMENT_INVALID. The parent handoff established seven required repairs:

1. Primary metric redefined as **mechanism-identity binding correctness** (HTTP postcondition execution demoted to separate verification measure)
2. **Verbatim positive control** actually executed with true denominator
3. **Real oracle arm** holding mechanism_id/fragment_id with declared difficulty ceiling
4. **Closed-top-bin ECE estimator** with preregistered UNKNOWN-precision definition (not substituted OOD abstention rate)
4. **Per-task server state reset** with logged per-task state hash
5. **Candidate resolver, goal generator, server code hashed into freeze.json**
6. **Degeneracy screen** executed and logged before any candidate arm runs confirming:
   - Lexical-overlap null sits strictly below preregistered headroom threshold
   - Comparison leg is non-empty (incumbent at min_confidence ≤ 0.5 or explicit non-empty substitute)
7. **Fixture with >1 mechanism per resource family across multiple verbs**, all parameter slots bound, no unbindable placeholders

This design incorporates all seven repairs in a single freezable packet.

---

## 2. Hypothesis and Falsifier

**Hypothesis (H1):** A fitted applicability gate operating on mechanisms with bound parameter slots will achieve mechanism-identity binding accuracy strictly above the lexical-overlap and random nulls (with paired family-blocked uncertainty), with calibrated abstention achieving UNKNOWN precision ≥ 0.85 and ECE ≤ 0.15 (bootstrap upper ≤ 0.18), demonstrating that semantic resolution is achievable without internal mechanism identifiers.

**Falsifier (F1):** The fitted resolver fails to exceed the lexical-overlap null on mechanism-identity binding accuracy with paired family-blocked uncertainty, OR the pooled false-accept rate exceeds 0.10, OR UNKNOWN precision falls below 0.85, OR global ECE exceeds 0.15 (bootstrap upper > 0.18), OR per-class ECE exceeds 0.15 (bootstrap upper > 0.18), OR the calibration gate is not fitted (abstention algebraically determined rather than measured).

## 3. Fixture Specification

### 3.1 HTTP Application (stdlib-only)

- **Server:** Python `http.server` with custom request handler (no external frameworks)
- **Endpoints:** 20 REST endpoints across 5 resource families × 4 verbs (CREATE/READ/UPDATE/DELETE)
- **Resource Families:** `users`, `posts`, `comments`, `albums`, `photos`
- **State:** In-memory dictionaries per resource family, fully reset per task
- **Persistence:** None (ephemeral per-task state)

### 3.2 Mechanism Registry

- **Total mechanisms:** 20 (4 per resource family: CREATE, READ, UPDATE, DELETE)
- **Parameter slots:** Every mechanism has non-empty `parameter_slots` list (e.g., `["user_id"]`, `["post_id", "title", "body"]`)
- **Action templates:** All templates executable with bound parameters. **Zero** unbindable `${...}` placeholders.
- **Intent strings:** Natural-language descriptions used for distillation (e.g., "create a new user", "retrieve a post by id", "update a comment", "delete an album")
- **Mechanism IDs:** Stable identifiers `mech_{family}_{verb}` (e.g., `mech_users_create`)

### 3.3 Goal Set (frozen before freeze)

| Category | Count | Description |
|----------|-------|-------------|
| paraphrased | 20 | Natural-language paraphrases of the 20 intents (unseen wording, same meaning) |
| underspecified | 10 | Goals missing one or more required parameters (e.g., "delete a photo" without photo_id) |
| composite | 10 | Goals combining multiple operations (e.g., "create a user then create a post for them") |
| OOD | 20 | Goals targeting operations/families not in registry (e.g., "schedule a post", "search users by email") |
| verbatim | 12 | Exact copies of the 20 distillation intents (subset, for PC-VERBATIM-INTENT) |
| no-applicable | 8 | Goals for which no mechanism applies (for NC-NO-APPLICABLE) |

**Total goals:** 80 (60 applicable + 12 verbatim + 8 no-applicable)

Goals are generated by a deterministic, seeded goal generator. The complete goal list with target mechanism_ids is hashed into `freeze.json`.

### 3.4 Embedding Model

- **Model:** `sentence-transformers/all-MiniLM-L6-v2` (cached locally)
- **Revision:** Pinned to specific commit hash (recorded in freeze.json)
- **Use:** Cosine similarity between goal embedding and mechanism intent embeddings for candidate resolver scoring

## 4. Arms

### 4.1 A-CANDIDATE (Fitted Applicability Gate Resolver)

**Architecture:**
1. **Scoring:** Cosine similarity between goal embedding and each mechanism's intent embedding
2. **Applicability Gate:** Fitted logistic regression `p_applicable = 1 / (1 + exp(-(w * cos_sim + b)))`
   - Trained on held-out validation split (20% of applicable goals, stratified by family)
   - Training uses mechanism-identity correctness as label (1 if family-correct, 0 otherwise)
   - Parameters `w`, `b` learned via maximum likelihood; **not** fixed algebraic transform
   - Fitted parameters logged and hashed into freeze.json
3. **Decision Rule:**
   - If `max(p_applicable) < threshold` → ABSTAIN (UNKNOWN)
   - Else → select mechanism with highest `p_applicable`
   - Threshold chosen to optimize validation F1 (separately logged)
4. **Parameter Binding:** Selected mechanism's `parameter_slots` bound from goal via slot-filling heuristic (keyword/entity extraction). All slots filled → EXECUTABLE. Any unfilled → ABSTAIN.

**Output per goal:** `mechanism_id`, `resolution_status` (EXECUTABLE/ABSTAIN/EXPLORE), `p_applicable`, `bound_parameters`, `confidence`

### 4.2 A-INCUMBENT (Reference Resolver at min_confidence ≤ 0.5)

- **Implementation:** The committed SpiderKernel `resolve()` method at min_confidence = 0.5 (the minimum for EXECUTABLE per audit probe)
- **Purpose:** Non-empty comparison leg for degeneracy screen and primary gate
- **Expected:** Mechanisms have `parameter_slots=[]` and `confidence=0.5` → EXECUTABLE on all applicable goals
- **Note:** This arm does NOT have parameterized induction; it tests the incumbent's resolution behavior at the executable threshold

### 4.3 B-LEXICAL-OVERLAP (Null Baseline)

- **Algorithm:** Max token Jaccard similarity between goal tokens and mechanism intent tokens
- **Selection:** Mechanism with highest Jaccard; ties broken by mechanism_id lexical order
- **Abstention:** Never abstains (always selects a mechanism)

### 4.4 B-RANDOM-ROLE (Null Baseline)

- **Algorithm:** Infer role (CREATE/READ/UPDATE/DELETE) from goal keywords; select uniformly from mechanisms with matching role
- **Abstention:** Never abstains

### 4.5 B-INTERNAL-ID-ORACLE (Oracle / Difficulty Ceiling)

- **Input:** Receives true `mechanism_id` and `fragment_id` for each goal
- **Behavior:** Returns the exact target mechanism
- **Expected accuracy:** 1.0 on mechanism-identity binding by construction
- **Declared ceiling:** If this arm achieves < 1.0, the fixture is defective → MEASUREMENT_INVALID

### 4.6 PC-VERBATIM-INTENT (Positive Control)

- **Goals:** The 12 verbatim goals (exact distillation intents)
- **Expected:** Mechanism-identity accuracy = 1.0, false_accept = 0.0, UNKNOWN precision = 1.0, ECE = 0.0
- **Denominator:** Must be > 0 (explicitly 12); logged and reported

### 4.7 NC-NO-APPLICABLE (Null Control)

- **Goals:** The 8 no-applicable goals
- **Expected:** Abstention rate = 1.0, UNKNOWN precision = 1.0 (vacuous), false_accept = 0.0
- **Denominator:** Must be > 0 (explicitly 8); logged and reported

## 5. Execution Protocol

### 5.1 Task Structure

Each task = one goal. All 7 arms execute on each goal in randomized order (43+ distinct orderings across tasks).

### 5.2 Per-Task State Reset (V7)

Before each task:
1. Server state dictionaries cleared and re-initialized
2. State hash = SHA256(JSON serialization of all server state) computed and logged
3. All arms execute against this identical starting state

### 5.3 Degeneracy Screen (V8) — Runs BEFORE Any Candidate Arm

Before A-CANDIDATE runs on any goal:
1. Run B-LEXICAL-OVERLAP on all 80 frozen goals → compute mechanism-identity accuracy
2. Run A-INCUMBENT on all 80 frozen goals → count EXECUTABLE decisions
3. **Screen PASS conditions (both required):**
   - (a) B-LEXICAL-OVERLAP accuracy < 0.90 (headroom threshold)
   - (b) A-INCUMBENT EXECUTABLE count > 0
4. If either FAILS → experiment halts, status = MEASUREMENT_INVALID, logged with full screen output

### 5.4 Calibration Fitting (V4)

Before main evaluation:
1. Split applicable goals (60) into train (80%) / validation (20%) stratified by resource family
2. Fit logistic regression on train set: `p_applicable ~ cos_sim` with mechanism-identity correctness as target
3. Select threshold on validation set to optimize F1
4. Log fitted `w`, `b`, threshold, validation metrics
5. Freeze these parameters (hashed into freeze.json)

## 6. Metrics (Stable Identities)

### 6.1 Primary Metric

- **mechanism_identity_accuracy:** Fraction of applicable goals where `selected_mechanism_id == target_mechanism_id`
- **Unit:** Proportion [0,1]
- **Comparison:** Paired family-blocked bootstrap (10,000 resamples) against B-LEXICAL-OVERLAP and B-RANDOM-ROLE
- **Blocking unit:** Resource family (goals sharing a family resampled together)

### 6.2 Secondary Metrics

| Metric ID | Definition | Threshold |
|-----------|------------|-----------|
| `false_accept_rate` | Fraction of EXECUTABLE decisions where `selected_mechanism_id != target_mechanism_id` (pooled across all goals) | ≤ 0.10 |
| `unknown_precision` | TP_abstain / (TP_abstain + FP_abstain) where TP_abstain = no-mechanism-applies AND abstain, FP_abstain = mechanism-applies AND abstain | ≥ 0.85 |
| `ece_global` | Expected Calibration Error with 10 equal-mass bins, **closed top bin [0.9, 1.0] inclusive**, no rows dropped | ≤ 0.15 (bootstrap upper ≤ 0.18) |
| `ece_per_class_max` | Maximum ECE across resolution status classes (EXECUTABLE, ABSTAIN), same estimator | ≤ 0.15 (bootstrap upper ≤ 0.18) |
| `calibration_is_fitted` | Boolean: calibration parameters learned on held-out validation, not fixed algebraic transform | = true |
| `degeneracy_screen_pass` | Boolean: both screen conditions PASS | = true |
| `pc_verbatim_accuracy` | Mechanism-identity accuracy on verbatim goals | = 1.0 (denom > 0) |
| `oracle_accuracy` | Mechanism-identity accuracy of B-INTERNAL-ID-ORACLE | = 1.0 |
| `nc_abstention_rate` | Abstention rate on no-applicable goals | = 1.0 (denom > 0) |

### 6.3 Verification Measure (Separate from Primary)

- **http_execution_success_rate:** Fraction of EXECUTABLE decisions where HTTP request returns 2xx/3xx
- **Threshold:** Reported separately; NOT part of primary gate
- **Purpose:** Verification that bound actions execute correctly; does not gate the semantic resolution claim

## 7. Decision Rule (Frozen)

### 7.1 Gate Evaluation Order

1. **Measurement Validity (V1-V11):** Any FAIL → MEASUREMENT_INVALID
2. **Degeneracy Screen:** FAIL → MEASUREMENT_INVALID
3. **Positive Control (PC-VERBATIM-INTENT):** FAIL or denom=0 → MEASUREMENT_INVALID
4. **Oracle Ceiling (B-INTERNAL-ID-ORACLE):** accuracy < 1.0 → MEASUREMENT_INVALID
5. **Null Control (NC-NO-APPLICABLE):** FAIL or denom=0 → MEASUREMENT_INVALID
6. **Calibration Fitted Check:** FAIL → MEASUREMENT_INVALID
7. **Primary Gate:** A-CANDIDATE mechanism_identity_accuracy > B-LEXICAL-OVERLAP AND > B-RANDOM-ROLE (paired family-blocked bootstrap, α=0.05, one-sided)
8. **Secondary Gates:** All must PASS (thresholds in Section 6.2)

### 7.2 Outcomes

| Outcome | Conditions |
|---------|------------|
| **SUPPORTS** | All gates 1-8 PASS |
| **FALSIFIES** | Primary gate (7) FAILS OR any secondary gate (8) FAILS |
| **MEASUREMENT_INVALID** | Any gate 1-6 FAILS |

**Note:** A valid FALSIFIES (status=COMPLETE, outcome=FALSIFIES) is a scientific result that bounds the resolver architecture. MEASUREMENT_INVALID means the experiment failed to validly test the hypothesis.

## 8. Validity Threats and Mitigations

| Threat | Mitigation |
|--------|------------|
| Construct validity: metric doesn't measure resolution | V1: Primary = mechanism-identity binding, not HTTP status. Verification measure separate. |
| Positive control unmeasured | V2: PC-VERBATIM-INTENT runs on all 12 verbatim goals; denominator logged. |
| Oracle not a true ceiling | V3: B-INTERNAL-ID-ORACLE receives mechanism_id; must achieve 1.0. |
| Calibration algebraic, not fitted | V4: Logistic regression fitted on held-out validation; parameters frozen. |
| ECE half-open bin defect | V5: Closed top bin [0.9, 1.0] inclusive; 10 equal-mass bins. |
| UNKNOWN precision misdefined | V6: Explicit TP/FP definition; NOT OOD abstention rate. |
| Shared server state confound | V7: Per-task reset + state hash logged. |
| Fixture non-discriminating | V8: Degeneracy screen catches lexical ceiling and empty comparison leg BEFORE candidate runs. |
| Code not bound to freeze | V9: All outcome-bearing code hashes in freeze.json. |
| Uncertainty ignores family clustering | V10: Paired bootstrap with family as blocking unit. |
| Fixture too easy (1 mech/family) | V11: 4 mechanisms/family, all verbs, all slots bound, zero unbindable placeholders. |
| Embedding model drift | Model revision hash pinned and recorded in freeze.json. |
| Goal independence from intents | Goal generator uses disjoint templates; overlap statistic computed per-goal vs own family target (not union). |
