## 4. Hypothesis (H1-H6) and falsifier

- **H1 install identity:** installed `src/spider/kernel.py` == carrier (`718efa6a` / blob `b15ed848`) and != pre-install (`46929b3a` / blob `cfec9866`).
- **H2 confidence flow:** parameterized mechanisms distill to confidence `0.9 >= 0.8` and can resolve `EXECUTABLE`; literal `distill()` candidates sit at exactly `0.5 < 0.8` and never resolve `EXECUTABLE` at the default threshold.
- **H3 positive inheritance on unseen identifiers:** each of the 6 families, given 4 induction observations and the unseen held-out parameter values, resolves `EXECUTABLE` at `0.9`, binds the requested unseen identifier, executes with fixture status `200`, and `verify()` true.
- **H4 safe refusal:** all 24 declared negative cases (out-of-support, missing-parameter, wrong-intent) are refused (`!= EXECUTABLE`, null `bound_action`, non-empty reason); wrong-intent / no-applicable-mechanism returns exactly `ResolutionStatus.UNKNOWN`.
- **H5 attribution:** correct-binding advantage over the frozen retrieval comparator on unseen held-out identifiers is strictly positive.
- **H6 honesty:** `TrajectoryCounters` advance exactly `retrieval_calls=3, verification_calls=2, repair_attempts=1`, with `model_calls=model_tokens=browser_actions=http_requests=latency_ms=0`.

**Falsifier:** with `AD-IDENTITY-BINDING` passing, the certificate FALSIFIES if `CONFIDENCE-FLOW` fails (parameterized confidence `< 0.8`, or literal confidence set `!= {0.5}`, or zero parameterized `EXECUTABLE`), **or** `AD-POSITIVE-ROUNDTRIP` has 0/6 passes, **or** `AD-NEGATIVE-ROUNDTRIP` fails (any unsafe case executed or wrong-intent not `UNKNOWN`). A partial positive (1-5/6) with intact refusals and confidence flow is `MIXED`, not `SUPPORTS`.

| `PC-PARAM-ROUNDTRIP` (= `AD-POSITIVE-ROUNDTRIP`) | positive control | 6 frozen families, unseen held-out identifiers | bind requested unseen identifier -> `200` -> `verify` true |

| `AD-IDENTITY-BINDING` | treatment assignment | installed file hash/blob | == carrier and != pre-install |

The comparator contrast is **correct-binding accuracy**, not a guaranteed action inequality. If treatment and comparator both bound the correct identifier (impossible here because the held-out ids were never observed, but possible if the instrument were broken), the measured advantage would be `0`, which is the honest outcome. `NC-ZERO-CONTRAST` is two-sided: it fails if the formula manufactures a win (placebo advantage != 0) and also if it can never report a win (oracle advantage <= 0).

            params[slot] = fallback
            used.add(fallback)
    return params

## 11. Validity threats and self-attack

- **Near-determinism / information ceiling:** the positive control almost surely passes once the audited carrier is present. Disclosed. The discriminating content is the confidence-floor separation, the typed refusals, the comparator contrast and the pinned identity, not the treatment's own success.
- **Comparator might be too weak:** addressed by using the frozen K=5 structural-nearest retrieval comparator on identical unseen inputs and by `NC-ZERO-CONTRAST`; a stronger retrieval baseline would only raise the bar, not invalidate a positive contrast.
- **Support-inference risk:** `distill_parameterized` infers per-slot support grammars from the induction set; if an unseen held-out value were out-of-support, H3 would fail a family. The frozen held-out values were checked in the probe to be in-support for all 6 families, and the fixture grammar accepts them.
- **Install identity could be satisfied by accident:** the check requires both the sha256 and the git blob, and requires difference from the pre-install identity; `b15ed848` is the audited carrier and no other content yields both.
- **Confounder: models.py/registry.py drift:** they are byte-identical to the carrier at DESIGN and are freeze artifacts; any drift breaks freeze-integrity -> `MEASUREMENT_INVALID`.
- **Promotion error:** `SUPPORTS` is necessary but not sufficient for promotion; the mandate requires an independent AUDIT PASS.
- **`B-SHIPPED-PRE-INSTALL` is identified by code identity, not executed separately:** the pre-install kernel lacks `distill_parameterized` and cannot be imported alongside the installed module under the same name; its blob/sha identity and difference from the installed file are recorded inside `AD-IDENTITY-BINDING` (`head_working_tree_preinstall_blob`, `preinstall_kernel_sha256`).
