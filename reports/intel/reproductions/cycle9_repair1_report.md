### 2.2 Causal explanation (facts above + inference labeled as such)

**FACT:** the dispatch agent performed its first full collection run
inside the SCOUT-mounted workspace rather than the repro-mounted one, and
the scout persist step's unconditional `git add -A` swept the resulting
evidence into the scout snapshot branch. This is mechanically proven by
(1) the files' presence only in that tree, (2) the persist commit's
timestamp falling strictly between the two runs, (3) zero evidence in any
prior scout branch, (4) absence of all three evaluator-facing artifacts
in the snapshot.

**INFERENCE (labeled):** the workspace mixup most plausibly occurred at
session start (both worktrees were mounted side-by-side with identical
layout; the run script resolves output paths relative to the current
working directory), and the sweep then happened silently because the
scout persist step does not scope its `git add -A` to Scout-owned paths.
The prior session left no narrative record of the mixup — consistent with
its having gone unnoticed (nothing in the harness errors when evidence
lands in the wrong checkout).
