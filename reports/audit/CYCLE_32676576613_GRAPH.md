replicated proof of concept of content-addressed fragment retrieval + oracle-

addressing, not a fragment-layer-vs-graph value-add result, no transfer
evidence, no speedup claims (correctly avoided).

## A. CLAIMS CHECKED

### C1 — Headline: "blind composition solved 2/3 unseen composites with 100% reused actions and zero exploration decisions, replicated"
- EVIDENCE: `results/graph/cycle2_20260824_021114.json`, `..._021804.json` (B-eval rows), summaries; code `graph/run_cycle2.py`, `graph/explorer.py` v5.
- RECOMPUTATION: independently re-parsed both raw JSONs. C2 inherit-blind: act=6 reused=6 novel=0 dp=0 status=success; C3: act=8 reused=8 novel=0 dp=0 success. Replication run identical in status/solved_by/action counts (wall-ms differ). memory_events show login fragment applied ×1 (4 steps) and pager fragment applied ×2 (C2) / ×4 (C3); arithmetic 4+2=6 and 4+4=8 closes exactly. Denominator check: total actions includes resets (counted novel); zero resets occurred; initial page loads excluded uniformly across conditions — no denominator trick found. store_before identical (1 distinct value) across all 12 eval runs → byte-restored KB verified.
- FAILURE MODES TESTED: denominator tricks (none), condition contamination (KB restored per run; `evaluation=True` suppresses fragment writes — verified in code), label/condition split bug of v3/v4 (fixed; final runs carry `design_freeze.max_applications=6`), hidden LLM (none; scripted only), replication cherry-pick (only two v5 files exist and both are cited).
- STATUS: **VALIDATED_FOR_CURRENT_TEST** (arithmetic + replication).
- LIMITS: "zero exploration decisions" is partly **oracle-guided**: the subgoal acceptance predicate terminates the iterate-until-accept loop at exactly page/3 or page/5. Disclosed as benchmark structure, but it must be stated that stopping is oracle-driven, not memory-driven.

### C2 — "Matched strong baselines on the SAME knowledge base solved 0 of 3"
- EVIDENCE: same raw files; `graph/planner.py`, `graph/nearest_traj.py`.
- RECOMPUTATION: graphbfs/traj/cold = 0 successes on all composites in both runs; per-row numbers match the report table exactly.
- FAILURE MODES TESTED: baseline strength. **Found weak by construction**: planner BFS marks states visited (`prev` dict) and never revisits, excludes self-loops, caps path depth at 6 → a single-pass BFS **cannot iterate** pagination beyond trained depth even though the required knowledge (successful edge root→page/2 via click `a|||||next`, signature stable across pages because href is not part of the target signature) IS in the transition graph. Verified from the store dump: no training edge originates at `quotes/page/2`. The traj baseline replays verbatim without iteration. A loop-permitting graph policy ("re-apply best outgoing edge while accept not yet true") plausibly solves the pager subgoals identically to fragment iteration.
- STATUS: **SURVIVES_AUDIT_WITH_LIMITS** — baselines are matched and honestly reported, but calling them "strong" overstates; they are no-loop/single-shot variants.
- MAXIMUM DEFENSIBLE WORDING: "beat the implemented single-shot graph-BFS, verbatim nearest-trajectory and cold baselines", not "beat strong baselines".

### C3 — Finding F1: "the fragment layer demonstrably adds value beyond its underlying transition graph"
- EVIDENCE: report F1; planner/explorer code.
- RECOMPUTATION: the decisive capability difference between inherit-blind and graphbfs on these tasks is the **iterate-until-accept application policy**, which the BFS baseline is denied by implementation, not by representation. The stored graph contains the reusable edge; the fragment layer additionally supplies content addressing. The experiment therefore does NOT isolate "fragment abstraction > transition graph"; it shows "addressing + iteration > addressing-free single-shot search".
- STATUS: **OVERCLAIMED** as an attribution claim.
- REQUIRED FIX: add an iterative/loop-permitting graph baseline (and optionally fragment-without-iteration ablation) before any layer-value claim.

### C4 — Route absence verified programmatically
- EVIDENCE: `route_absence` blocks in both JSONs; `graph/absence.py`; unit tests `tests/test_graph_cycle2.py::RouteAbsenceTests`.
- RECOMPUTATION: strict adjacent-pair test passed for all composites; composite ids absent from transitions; max fragment span 4 < minimum composite chain. Code review: the checker chains ALL transitions including failures (conservative — more states checked, more chances to violate); unit tests demonstrate it detects a violating adjacent pair and a whole-task collision. Adjacency-over-all-pairs is sufficient to block piecewise trajectory concatenation.
- STATUS: **VALIDATED_FOR_CURRENT_TEST**.

### C5 — Consumer blindness: "NO fragment IDs, NO goal-signature keys ... only natural-language subgoal descriptions"
- EVIDENCE: `explorer.py::_query_text/_candidates`; tasks2 docstring; memory_events.
- RECOMPUTATION: sig/hint channels are genuinely closed for eval (blind branch never reads `sub["sig"]`; GENERIC hint map gated off; fills values are disclosed task data). UNKNOWN stays UNKNOWN (C1 named-book and category returned zero candidates and were reported as exploration/unsolved — no ground-truth injection). **BUT** `_query_text` appends `sub["keywords"]` to the description, contradicting both docstrings ("retrieve memory ONLY through these descriptions"). Counterfactual scoring with my independent reimplementation (which reproduces every recorded ranking exactly when keywords are included): without keywords, login still retrieves (cov .33) but **all pager-subgoal queries return NO candidates** (`eval.c2.page3/c3.page5/c1.page2 → []`). The keyword "next" is load-bearing for the pagination retrievals that produce the headline's composed depth.
- STATUS: **SURVIVES_AUDIT_WITH_LIMITS** at best; headline wording "only natural-language descriptions" is **OVERCLAIMED** as measured. The mechanism still works for the auth/login piece desc-only; the depth-composition piece currently depends on a benchmark keyword channel.
- ALSO NOTE: eval descriptions are near-verbatim copies of training descriptions (C2 login description is character-identical to T_Q_login's; pager descs differ by one digit — and the scorer does NOT understand digits: "page 3" matches via 'page'/'next', depth comes from iteration). Robustness to paraphrase is untested.

## B. ENVIRONMENT FINDINGS

- **"auth-gated" is wrong.** Live probe by auditor: `https://quotes.toscrape.com/page/3/` returns HTTP 200 with full quote content, anonymously (no logout marker). Nothing gates the pagination on either site; the login step is task-defined, not environment-required. The report's phrase "auth-gated, iterated navigation" inflates perceived difficulty. Correct wording: "form-auth composition plus iterated pagination on non-gated listing pages". This also means C2/C3 would decompose if a future agent skips login — worth testing as a robustness probe, actually informative.
- F4 (the-internet skeleton DOMs) documented with dropped tasks; health gating demand is legitimate.
- F2/F3 (ordinal goals unaddressable; df-pruning brittleness) confirmed by my independent scoring: mystery AND fiction category subgoals return zero candidates at eval time (MIN_MATCH=2 rejects 1 surviving pair after pruning).
